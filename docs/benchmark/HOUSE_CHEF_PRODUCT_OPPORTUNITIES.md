# House Chef Cyprus Product Opportunities

## P0 — protect trust and public correctness

| Opportunity | Why now | Acceptance signal |
|---|---|---|
| Published-content quality gate | Public detail cards and pages must never imply missing editorial or media facts | Published recipe/blog gate is auditable; no unsupported state leaks |
| Approved-media truthfulness | Real food media must be distinguishable from a branded/text-only fallback | Public card and detail rendering have an explicit approved-media state |
| SEO/public leakage audit | Drafts and review metadata create major trust and search risk | Tests confirm zero draft, review, evidence, or internal metadata leakage |
| Contact request operations | Public feedback needs an accountable path | Submitted contact request is rate-limited, consented, audited, and admin-only |

## P1 — improve the first useful journey

| Opportunity | Original House Chef solution | Dependency |
|---|---|---|
| Intent-led discovery | One search and filter contract across title, ingredients, aliases, and verified attributes | Taxonomy/canonical route plan |
| Curated collection landing pages | Cyprus/Mediterranean seasonal, method, meal, and ingredient routes with editorial ownership | Approved content threshold |
| Recipe detail utility | Print view, section visibility rules, reviewed data panel, honest related content | Quality-gate data |
| Editorial destination | Guides with source status, contents, related recipes, and text-only mode | Editorial quality gate |
| Retention basics | Collections, saved filters, shopping-list reliability, recently viewed controls | Privacy/retention controls |

## P2/P3 — only after foundations

- P2: consent-aware aggregate analytics, performance budgets, newsletter preference center, provenance-rich media variants.
- P3: ratings, comments, creator profiles, recipe submissions, sponsorship, affiliation, premium plans, or any public community layer.
